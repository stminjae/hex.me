My Product Feedback

By Minjae Lee

I built a notebook and a Generative App in Hex, then kept working on them from Claude through the Hex MCP server. Here is what helped me and what I would change, grouped by product area.

  1. 1NotebooksRun modes, staleness markers and SQL to Python with no switching cost.
  2. 2Notebook AgentReviewable diffs. It needs business context to pick the right columns.
  3. 3Generative AppsMy top priority: hard to finish without writing code.
  4. 4Hex MCP serverSees the whole notebook, then stops at the notebook's edge.

01Notebooks

The core editing experience.

What works

Run modes and staleness

Hex knows which cells depend on which, so I never have to remember what to rerun.

A stale marker means I never trust an old number, which matters more once an agent is writing cells.

SQL to Python, no switching cost

My SQL result was already a dataframe, so I did the what-if math in Python with no export step.

SQL formatting

One click formats SQL to a house style, so agent-written queries are easy to review.

02Notebook Agent

The AI that writes and edits cells inside a notebook.

What works

Diff review

The agent showed its changes like a pull request and flagged its own risk.

What I'd improve

The agent needs context

With plain business language, it picked the wrong columns.

Ask: nudge new users to add a semantic model or table descriptions first.

The details

In my notebook, a loyal customer is orders >= 7, but the agent can't know that without a definition. Hex's own AI setup guide lists semantic models and column descriptions as the fix, yet nothing in the product prompts you to do it.

03Generative Apps

Turning notebook results into an app people can use.

What I'd improve

Hard to finish without code

Editing needs JavaScript, even for a label or a chart's data source.

I couldn't see which dataframe feeds which chart, only a cell ID.

A new cell I connected loaded forever, with no error.

Ask: click a chart to see and change its source, and show a clear error when data fails to load.

The details

Each chart in charts.js reads data with useHexData("<cellId>"). The ID is an opaque string, not a dataframe name, so I added my own Source caption under all 7 charts to trace them. Repointing a chart means hand-editing that ID.

04Hex MCP server

Working on Hex from Claude, outside the Hex app.

What works

Whole-notebook view

Claude saw every cell at once, caught the loyalty rule repeated about 12 times, and suggested defining it once upstream.

What I'd improve

MCP stops at the notebook

It can't touch app code, cell names or cell order, or read Python outputs.

Ask: app-code access, plus move-cell and rename-cell tools.

The details
  • update_cell changes only the source and data connection. There is no label or location.
  • create_cell does take label and insertAfterCellId, so moving a cell means delete and recreate. That issues a new cell ID and breaks the app's useHexData link.
  • get_cell_output is documented as SQL-only, so my market_conversion Python cell can't be read back.
  • list_cells returns code, SQL and markdown. No tool reads or writes App.js or charts.js.
